module kl::test::context

class context

#class context

What a test checks through. A failed check is counted and reported, and the test goes on; a failed require ends it.

Constructors

#public context()

A context with no failures. expect_panic needs one run made.

#public context( u64 index, u64 call )

The context run gives the test at index in its list. A call above 0 makes the process one expect_panic started, which runs only that call's body, counting from 1, and skips the calls before it. For run; a test never needs it.

Methods

Whether any check has failed.

#@located public void check_eq( f64 a, f64 b )

Counts a failure if a and b differ, reporting both and the line that called it. A NaN equals nothing, itself included.

#@located public void check_eq( bool a, bool b )

Counts a failure if a and b differ, reporting both and the line that called it.

#@located public void check_eq( const ref textual a, const ref textual b )

Counts a failure if a and b hold different bytes, reporting both, quoted, and the line that called it.

#@located public void require( bool condition )

Ends the test if condition is false, as a panic at the line that called it.

#@located public void expect_panic<F>( const ref textual message, F body ) where F : fn() -> void

Counts a failure unless body panics with a message containing message, reporting the line that called it.

body runs in a process of its own: this program started again, running the test from its start but skipping the bodies of the calls before this one. Nothing body changes, checks on this context included, reaches the test, and a test whose path to this call can differ from one run to the next, by a clock or a random key, may not reach it there. Only a panic is expected: an assert is off in release builds.
